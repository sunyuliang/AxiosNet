Architecture Overview

AxiosNet 系统架构总览 ／ 全链路分层

axios 风格的 .NET HTTP 客户端。自上而下分五层：调用入口 → 请求管线 → 尝试管线（中间件链）→ 连接与传输 → 运行时资产。 序列化、缓存、遥测、错误模型横切各层。

分层总览

从调用方写下的一行代码，到 socket 上发出的字节，一共穿过五层。每层只依赖下一层，横切能力挂在层侧。

02

一次请求的完整管线

固定顺序驱动，阶段编号与 AxiosClient.Pipeline.cs 的注释逐条对应。三条路径决定这条请求会不会真的出门：短路响应、缓存命中、校验直接抛错。

  1. 00
    入口守卫 · 在途计数EnterInFlight

    先复核释放标记，再自增 _inFlight。这个计数的用途是把 Dispose() 的资源释放推迟到最后一个请求结束，不是并发上限；位置在 try 之外，抛时名额还没占上。

  2. 01
    合并配置MergeEffectiveConfig

    Defaults.Clone() 与本次请求配置合并，得到本次唯一生效实例；已是合并产物则直接用。

  3. 02
    实例级选项校验ValidatePerRequestOptions

    七项实例级选项（Proxy / Credentials / WithCredentials / MaxRedirects / Pool / MaxInFlight / MaxQueue）构造期已固化，写不进单次请求。这里只校验两条：传输档必须已登记、凭据来源与显式 Authorization 头不得并存。

  4. 2.5
    凭据解析ResolveCredentialAsync

    把凭据槽位（AxiosCredential）解析成 Authorization 头值；提供方自己写的头不算冲突，同一请求内不会被无谓调用第二次。

  5. 03
    请求拦截器InterceptRequestAsync

    按注册逆序执行（与 axios 一致），可异步改写配置、URL、正文与头。

  6. 3.5
    冲突校验与补解析

    判的是拦截器之后最终要发出的那份配置：显式头与槽位并存才报冲突；槽位被换掉则重新解析。

  7. 4a
    规范化ApplyAutoResponseType

    泛型 <dynamic> / <object> 与 Stream 自动切换响应形态，只在未显式指定时生效。

  8. 4b
    范围校验ValidateRangeConfig

    与「是否真的发出请求」无关，因此刻意排在短路之前。

  9. 4c
    短路响应

    配置了 ShortCircuit 就不发请求，直接交付现成响应（mock / 回放 / 预置缓存）。

    ↳旁路跳过并发闸门、编码、租约、发送、重试、熔断与遥测；反序列化、transformResponse、validateStatus 与响应拦截器照常执行
  10. 4d
    闸门与截止点ResolveConcurrencyGate / TotalTimeoutBudget.Start

    按需懒建并发闸门（没配 MaxInFlight 就不建，默认路径零分配）；总预算换算成绝对时间戳，各分支共享同一截止点。这一步只解析，真正占位在链内的 Gate 中间件。

  11. 5
    编码与成型5a transform · 5b plan · 5c template

    transformRequest → 最终 URL 与协议协商（含 HTTP/3 前置校验）→ 建请求模板（正文 + 头）。正文只准备一次、重试复用，进度与限速状态都挂在正文上。

  12. 5.5
    缓存查询AxiosCache

    按 URL 与身份取键。命中 2xx 直接返回；同键并发只发一次，跟随者等领导者结果；新鲜条目未命中时取带校验器的旧条目，把校验器写成条件头。

    ↳旁路命中、或跟随者拿到结果，都不发请求；请求侧 no-store / no-cache 则跳过查询（仍会尝试落库）
  13. 6
    发送RunResponseInterceptorsAsync + AxiosAttemptPipeline

    响应拦截器责任链包在外面，里面是尝试管线：重试 → 备用端点 → 熔断 → 对冲 → 闸门 → 审计 → 终端。

  14. 6b
    后处理

    状态码 → 异常；流式正文接计时流并转交所有权；条件请求 304 单独计为校验复用；领导者落库、放行跟随者；最后上报成功（span 覆盖到调用方真正拿到结果）。

  15. 收
    收尾finally

    释放请求模板（可能是调用方的 FileStream / FormFile）；401 且走托管凭据时把正文交给声明式门面做一次性重放；在途计数最后归还。

03

尝试管线：六层中间件链

一次尝试 = 一条可组合中间件链。位置即语义：越靠外，调用次数越少；越靠内，越贴近真实发送。真正的发送恒在最内层，不在可编排列表里，也换不掉。

Attempt.Retry最外层 · 每次重试重过一遍内层全部环节 · 最多 N+1 次
Attempt.Failover每个端点各一次 · 失败端点跨请求冷却
Attempt.Circuit按 host:port 计数 · 连续失败 + 滚动窗口失败率取「或」
Attempt.Hedging并发分支 · 先成功者胜出
Attempt.Gate在途并发闸门 · 槽位由中间件自己兜底归还
Attempt.Audit紧贴终端 · 未订阅时零分配
Terminal · 一次真实发送 取池租约 → 选定传输档 → Handler 发送 → 读状态与头 → 正文按需缓冲或流式转交
实际发送次数 = (N+1) × (端点数+1) × (1 + MaxHedges)　·　落在外层（每次请求一次）的自定义逻辑应改用响应拦截器

中间件编排规则

  • Append追加到链尾，比审计更贴近终端，必须能并发执行
  • InsertBefore锚点不能是链首 —— 插到最外层等于每次请求一次，会抛错
  • Create整体重排；同一内置项出现两次会被拒绝
  • 固化链在客户端构造期编译一次并固化，请求内按 ctx.Config 分支

总预算 Deadline

  • Timeout一次尝试的预算
  • TotalTimeout整条请求（含排队、重试、对冲）
  • 实现入口换算成绝对时间戳随上下文传，各分支共享同一截止点
  • 流式读正文同样计入，等待被截断即到点

熔断判定

  • 两条规则连续失败次数、滚动窗口失败率，取「或」
  • 恢复期只认领到探测名额的请求，成功才逐步放开
  • 策略IAxiosCircuitPolicy 可替换，内置 CircuitBreaker 带准入票
04

连接与传输：池、传输档、Handler

每 origin 一条调优过的 Handler 共享长连接；一条池可挂多条出口。key 由调用方给，不做配置指纹 —— 同一个 key 再传一份不同配置直接抛错，而不是悄悄复用错的池。

从租约到字节

HttpConnectionPoolkey / GetOrCreate / 统计 → PooledEndpointper origin · 生效选项 → TransportProfileegress-a · 代理/证书/Cookie
HandlerFactory自建 或 DelegatingHandler → SocketsHttpHandlernet6 / net8 → DNS · TCP · TLS · HTTP/2 · HTTP/3长连接复用
PoolLease借出 → 归还 ↔ StreamOwner流式成功时接管租约 · HttpClientHandlernetstandard2.0 资产

预热只建 origin 节点与静态首用成本，不预先建连；池指标不带 host，用 span 定位。

池选项要点

  • MaxConnectionsPerServer每 origin 并发连接上限
  • PooledConnectionLifetime连接寿命，配合 DNS 变更
  • KeepAlivePing*三件套进 SameOptions，Delay 默认 Infinite
  • HandlerFactory替换传输层；默认工厂按 TFM 返回不同 Handler 类型
  • AddTransport一条池声明多条出口，按请求选 Transport.Profile
  • 所有权自建池_ownsPool 随客户端释放；注入或 GetOrCreate 共享的池不归客户端，由调用方 Release
05

声明式客户端：一份声明，三条通道

用模型或接口描述请求，由 ApiClient 生成调用。运行时反射通道与编译期生成通道产出同一套元数据契约，因此可以逐类型迁移到 AOT。

声明形态 WebAPI/

模型式[Get("users/{id}")] class GetUserRequest : IApiRequest<User> 或 接口式[Get("users/{id}")] Task<AxiosResponse<User>> GetAsync([Path] int id) → ApiClient.Create<T>()统一执行入口 → IAxiosClient

特性集中在 WebAPI/Attributes/：HTTP 动词与路径、参数绑定、请求头、编码、部件、流式、鉴权、值格式化。

运行时反射（JIT）
  • RequestModelDeclarationReader
  • InterfaceDeclarationReader → InterfaceBuilder
  • 形状与访问器走 Reflection/ + ReflectionCache
  • 未生成代理时回退 DispatchProxy（仅 JIT）；AOT 下 Create<T> 提前拒绝
编译期源生成（AOT）
  • RequestModelGenerator + InterfaceEmitter
  • 烘焙代理与形状快照，ModuleInitializer 注册
  • GeneratedMetadataRegistry 命中即用烘焙元数据
  • 与 Reflection/ 对称：AOT 下整块反射可裁掉
设计期 CLI
  • SpecParser → SpecNormalizer → RefResolver
  • SchemaMapper → ApiModel → CSharpEmitter
  • 支持 --check、--dry-run 与确定性输出
  • 产物即上面两种声明形态的 C# 代码
共享元数据层
  • AxiosMetadata / ShapeRegistry / ShapeBuilder
  • BindingPlan 与值来源 IValueSource
  • FormatRules + AxiosConfig.ValueFormatter
  • 凭据：ApiCredential / AccessTokenManager（令牌缓存、单飞刷新）；401 重放由 ApiClient 做一次
06

横切能力

不归属单一层，被各层共同调用。每张卡片对应一个可替换的抽象。

序列化 Serialization/

唯一抽象 IContentSerializer：按媒体类型查表（精确 → 别名 → +json 结构化后缀），未命中回落表内默认项。

  • 默认SystemTextJsonSerializer
  • 内置XmlContentSerializer
  • 注册AxiosContent.Register / ContentSerializerRegistry

缓存 Cache/

按 URL 与身份缓存 2xx 响应；同键并发只发一次；存储可替换。

  • 存储IAxiosCacheStore / MemoryCacheStore
  • 复用IAxiosCacheRevalidationStore、ETag / 304
  • 策略新鲜度模式 + 请求 / 响应指令 + Cache-Control 解析

可观测 Telemetry/

trace / metrics / events 三路，默认开启；无人订阅时零产出。

  • 入口AxiosTelemetry + GuardedTelemetrySink
  • 信号ActivitySource「AxiosNet」/ Meter / DiagnosticListener
  • 事件AxiosRequestEvents、尝试级审计事件

错误与取消 根命名空间

请求执行失败统一为 AxiosException，带稳定 Code；AOT 元数据缺失另抛专用异常。

  • 分类FailureClassifier / CancellationClassifier
  • 口径预算耗尽（未发出）不计熔断失败、不重试、不换端点
  • 判别Axios.IsAxiosError / Axios.IsCancel

元数据与形状 Metadata/ + Reflection/

对象形状（成员表、默认值、格式化规则）在生成期或首次使用期构建，之后冻结复用。

  • 构建ShapeBuilder / ObjectShapeBuilder / ShapeCache
  • 读取ValueFormatReader / PreformattedValue
  • 反射ObjectShapeReflection / JsonSerializerJit（仅 JIT）

兼容层 Compatibility/

netstandard2.0 资产的功能子集由编译期分叉实现，现代资产不降级。

  • 内容polyfill / global using 别名 / BCL 扩展 / 平台 helper
  • 差异HTTP/1.1、HttpClientHandler、仅 gzip、接口纯声明
  • 依赖9 个微软第一方 BCL 兼容包，NuGet 自动带入
